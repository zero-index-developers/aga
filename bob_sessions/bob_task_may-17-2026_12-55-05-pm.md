## Error Analysis

**Root Cause:** The `.env` file is missing in the Docker container at `/var/www/.env`

**Why this happens:**
1. The `entrypoint.sh` script tries to run `php artisan key:generate --force` when `APP_KEY` is empty
2. Laravel's `key:generate` command attempts to read and modify the `.env` file
3. The `.env` file doesn't exist in the container because:
   - Only the `.env.example` file is in the repository
   - The Dockerfile doesn't copy or create a `.env` file
   - Docker Compose passes environment variables directly, but Laravel still expects a physical `.env` file for the `key:generate` command

**Solution Options:**

**Option 1: Create .env from .env.example in entrypoint.sh (Recommended)**
Modify `api/entrypoint.sh` to copy `.env.example` to `.env` before running key:generate:
```bash
if [ ! -f .env ]; then
  cp .env.example .env
fi
```

**Option 2: Skip key:generate when APP_KEY is set via environment**
Since Docker Compose already sets `APP_KEY` via environment variables, you could remove the key:generate step or make it conditional on the `.env` file existing.

**Option 3: Add .env to Dockerfile**
Copy `.env.example` as `.env` in the Dockerfile during build.

**Additional PHP Warnings:**
The deprecation warnings are from `php.ini` settings:
- `mbstring.http_input`, `mbstring.http_output`, `mbstring.internal_encoding` are deprecated in PHP 8.4
- `allow_url_include` directive is deprecated
- Unknown encoding "pass" in ini setting

These should be removed from `api/php.ini` or `dev.php.ini` to clean up the warnings.
